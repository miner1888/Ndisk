# NDisk — 多用户网盘

基于 Rust / axum 的多用户网盘服务,支持分片断点上传与小文件直传(服务端自动判定)、断点续传下载、文件移动(拖拽)、在线预览与编辑(文本 / 表格 / Word / PPT 大纲 / PDF / 音视频)、目录级权限控制、匿名分享链接与 HTTPS。前端为内嵌静态页面(随二进制分发,无需外部依赖),桌面与移动端(安卓使用习惯)均已完整适配。

同一套代码同时支持 **Linux 与 Windows**,单文件部署,数据落在 SQLite。

## 功能特性

- **多用户与权限**:验证码登录(HttpOnly 会话 Cookie + Bearer 令牌)、密码修改、用户权限开关(上传 / 下载 / 删除 / 建目录);每个账号独立个人空间,普通用户只能管理自己的文件,管理员可管理所有用户空间;游客对公开目录只读
- **共享目录与规则**:管理员挂载任意本机目录,按子目录设置 游客 / 登录 / 管理员 三级访问,规则向下继承、深路径优先
- **文件操作**:网格 / 列表视图、搜索、排序、新建文件夹、重命名、删除(递归)、批量打包下载;全选(Ctrl+A)与鼠标滑动框选批量选中;防路径穿越与危险文件名(含 Windows 保留名)
- **文件移动**:拖拽文件 / 文件夹到目标文件夹或面包屑即完成移动,支持多选整批移动;磁贴菜单与底部选中栏提供「移动到…」文件夹选择器(面包屑导航 + 子文件夹列表);同共享内任意层级移动,含冲突 / 自嵌套 / 归属校验
- **相册**:个人空间下方独立入口,递归聚合空间内全部**图片与视频**,只显示缩略图(视频带播放角标,不显示文件名);单击查看,图片整页查看器支持左右按钮 / 滚轮 / 方向键 / 触屏滑动切换,视频在线播放;详情查看名称 / 大小 / 位置 / 时间
- **媒体缓存治理**:缩略图与转码产物统一登记,源文件删除/改名/覆盖时联动回收,超过 30 天未用自动过期,孤儿目录自动清扫;管理后台「系统维护」可查看占用并一键清理
- **视频转码**:需要转码的视频由 ffmpeg 软件编码(libx264)转成 mp4 播放,不依赖显卡驱动;未安装 ffmpeg 时此类视频只能下载。后台「系统维护」可开启**上传视频自动转码替换**(默认关闭):开启后新上传的非 MP4/WebM 视频在后台排队转为 H.264 MP4 并原子替换原文件,失败保留原文件
- **在线预览与编辑**:图片整页查看器(左右按钮 / 鼠标滚轮 / 方向键切换、Esc 退出);音频使用底部常驻播放器(靠下居中的圆角卡片,可拖动移动、上一首 / 下一首、拖动进度,播放中不影响浏览其它目录);文本(UTF-8 / GBK 自动识别)、表格 xlsx / xlsm / xls / ods / csv / tsv(保留格式与合并单元格渲染,编辑保存不破坏其它工作表)、docx、pptx 大纲、pdf、视频(ffmpeg 转码播放)、视频与图片缩略图
- **智能上传**:服务端按文件大小自动判定——小于等于分片大小(`--chunk-size`,默认 8M)的文件走**单请求直传**(原子落盘,失败自动回退),大文件走**分片断点续传**(单片失败自动重试 3 次、60 秒无进展超时、断点续传、空文件支持);跨文件系统(独立磁盘 / Docker 卷)自动回退复制;任务面板逐条显示进度,完成显示绿色对号,失败显示红色叉并可重试
- **详情视图**:大小(文件夹统计包含的文件 / 文件夹数)、位置面包屑、创建 / 修改时间
- **分享链接**:文件级匿名访问页,有效期与访问计数,权限回收即时生效,过期链接后台定期清理
- **下载**:Range 流式播放与**断点续传下载**(标准 HTTP 206,下载工具中断可自动续传)、HMAC 签名直链(免登录、有效期)、安全响应头;批量打包为流式生成(服务端内存占用恒定,打包上限 2GB,临时文件下载完自动删除)
- **移动端**:完整适配安卓使用习惯——侧栏抽屉(汉堡展开 / 遮罩点按 / 左滑收起 / 左缘右滑展开)、右缘左滑全局返回(查看器 / 后台 / 相册 / 搜索 / 上级目录逐级回退)、文件区轻点打开 + 长按菜单 + 左滑返回上级、右下角悬浮按钮(上传 / 新建文件夹)、下拉刷新、搜索展开式工具栏、弹窗底部面板化、图片查看器全屏滑动切图
- **管理后台**:用户管理(创建 / 权限勾选卡片式列表 / 重置密码 / 删除)、共享目录与访问规则、系统维护(环境信息 / 缓存清理 / 自动转码开关)、HTTPS 证书、修改密码;顶栏常驻返回,移动端横滑分类导航 + 卡片流布局
- **品牌标识**:内置 logo(`web/logo.svg`),浏览器标签页 / 侧栏 / 登录页统一使用;Windows 编译时由 `build.rs` + `assets/ndisk.ico` 自动写入 exe 资源,资源管理器与任务栏显示同一 logo
- **HTTPS**:管理界面在线上传 / 删除证书,rustls 热生效

## 用户空间与权限模型

- **每个账号一个独立目录**:`data/users/<用户名>/`,内容互不可见(含管理员);账号创建时即生成对应空间,不做任何历史数据兼容。
- **普通用户**:只能看到和管理自己的个人空间;在管理员发布的公共共享目录里,只能上传 / 新建 / 修改 / 删除**自己创建**的条目,别人创建的文件(以及服务器直接放入的文件)只读。
- **管理员**:可以看到并管理所有用户的个人空间(侧栏"用户空间"),管理公共共享目录、访问规则与账号。
- **私有空间**:个人空间只对属主与管理员可见,游客与其它用户即使拿到共享 ID 也无法访问。
- **公共共享目录**:管理员挂载本机任意目录,按子目录设置 游客 / 登录 / 管理员 三级访问;游客对所有目录只读,登录用户的可写操作还受账号能力开关(上传 / 下载 / 删除 / 建目录)约束。
- **条目归属**:共享目录内的文件 / 文件夹在创建时会记录创建者,重命名 / 移动会跟随更新,删除时清理;这是"普通用户只能管理自己的文件"的落地依据。

## 快速开始

需要 Rust 工具链;媒体转码与缩略图可选安装 `ffmpeg`(或用环境变量 `NDISK_FFMPEG` 指定路径)。

```bash
cargo build --release
./target/release/ndisk
```

默认监听 `0.0.0.0:9000`,数据目录 `./data`,初始管理员 `admin / admin123`(请尽快修改)。

release 构建已内置体积优化配置(strip / LTO / 单编译单元 / panic=abort / `opt-level="z"`),单文件约 6MB;若对吞吐更敏感可把 `Cargo.toml` 中 `opt-level` 改为 `2`(约 9MB)。

常用写法:

```bash
ndisk -p 18080                     # 换端口
ndisk -l 127.0.0.1:8080            # 只监听本机
ndisk -p8080 -d D:\ndisk-data      # 短参数可紧贴取值
ndisk --port=8080 --host=127.0.0.1 # 长参数支持 = 赋值
ndisk -h                           # 查看全部参数
```

端口被占用时:显式指定的端口会直接报错并给出排查建议;使用默认端口时会自动向后找一个可用端口并在日志中提示(Windows 上 9000 常落在 Hyper-V / WSL / Docker 保留的端口段,绑定会报 10013)。

### 关于 `data/media` 目录

`data/media/` 是**派生缓存**,不是用户文件,可以随时删除(播放/浏览时会按需重建)。里面按 `(共享, 相对路径)` 的哈希分目录,存放:

- `f.mp4`:需要转码的视频的 mp4 产物
- `thumb.jpg` / `img.jpg`:视频封面 / 图片缩略图

清理策略(自动,无需人工):

- 源文件被删除、重命名或覆盖时,对应缓存立即回收,空目录一并删除
- 服务启动时与每小时的后台任务会清理:源文件已不存在的缓存、超过 30 天未访问的缓存、以及没有任何索引引用的孤儿目录
- 管理后台 → 系统维护 可查看缓存占用(总大小 / 缩略图 / 转码产物 / 目录数)并一键清理

### 关于上传与下载

- **上传判定**:上传前先创建会话,服务端按文件大小返回分片数——小于等于分片大小的文件自动折叠为单片,前端改走直传接口(单请求原子落盘,无会话);大于分片大小的文件走分片上传,单片失败自动重试,会话 48 小时内可断点续传,超期由后台任务清理(含无主分片目录)
- **下载续传**:所有下载端点支持标准 HTTP Range(206 Partial Content),浏览器或下载工具中断后可自动续传;签名直链同样支持
- **打包下载**:多选后申请签名直链,浏览器原生流式下载;服务端把打包写入临时文件再流式发送,内存占用与打包体积无关,发送完成或客户端中断时自动删除临时文件
- **自动转码替换**:后台开关默认关闭;开启后新上传的非 MP4/WebM 视频由后台逐个排队转码(串行避免挤占 CPU),成功后原子替换原文件,失败保留原文件并记录日志

### Windows 启动失败排查

Windows 下若出现 `监听 0.0.0.0:9000 失败: ... (os error 10013)`,说明端口不可用(访问被拒绝),按下面顺序处理:

```bat
:: 1) 看端口是否被别的程序占用
netstat -ano | findstr :9000

:: 2) 看端口是否落在系统保留段(Hyper-V / WSL / Docker 会保留)
netsh interface ipv4 show excludedportrange protocol=tcp

:: 3) 直接换端口启动(最省事)
ndisk.exe -p 18080

:: 4) 只想本机访问
ndisk.exe -H 127.0.0.1 -p 18080

:: 5) 需要释放保留端口(管理员,重启后失效)
net stop winnat && net start winnat
```

### Windows 构建

```powershell
cargo build --release   # 生成 target\release\ndisk.exe,自动带上 assets\ndisk.ico 图标
```

图标与版本信息由 `build.rs` 通过 `winres` 写入 exe 资源(仅 Windows 目标生效,Linux / macOS 构建忽略)。
若未安装资源编译器(`rc.exe` 或 MinGW 的 `windres`),构建仍会成功,只是 exe 不带自定义图标,并在构建日志中提示。

### 自动发布(GitHub Actions)

`.github/workflows/release.yml` 已内置自动发布流水线,推送到 `main` 即触发:

1. 版本号自动递增:从 `0.0.1` 起每次 +1 patch(读取最新 `v*` tag),自动写入 `Cargo.toml` / `Cargo.lock` 并提交、打 `v*` tag(`--version` 输出随之更新)
2. 双平台编译:Linux x64(ubuntu)+ Windows x64(windows,自动嵌入图标与版本信息),编译前先跑 `cargo test`
3. 自动创建 GitHub Release 并上传产物:`ndisk-<版本>-linux-x64.tar.gz`、`ndisk-<版本>-windows-x64.zip`

需要更高位版本号(如升 minor / major)时,手动推一个 `v1.0.0` 形式的 tag 即可,下一次自动递增将从它继续。
### 命令行选项

| 选项 | 简写 | 说明 | 默认值 |
| --- | --- | --- | --- |
| `--listen <addr>` | `-l` | 监听地址,可写 `host:port` 或只写端口 | `0.0.0.0:9000` |
| `--port <port>` | `-p` | 监听端口 | `9000` |
| `--host <addr>` | `-H` | 监听网卡地址(只允许本机用 `127.0.0.1`) | `0.0.0.0` |
| `--tls-listen <addr>` | `-t` | HTTPS 监听地址(配置证书后启用) | `0.0.0.0:443` |
| `--tls-port <port>` | | HTTPS 端口 | `443` |
| `--data <dir>` | `-d` | 数据目录 | `./data` |
| `--admin-user <name>` | `-u` | 初始管理员用户名 | `admin` |
| `--admin-pass <pw>` | `-w` | 初始管理员密码 | `admin123` |
| `--chunk-size <size>` | `-c` | 上传分片大小,支持 `8M` / `8MB` / `8388608` | `8M` |
| `--help` | `-h` | 显示帮助 | |
| `--version` | `-V` | 显示版本 | |

### 环境变量

- `NDISK_FFMPEG`:ffmpeg 可执行文件路径(默认在 PATH 查找)
- `RUST_LOG`:日志过滤(默认 `ndisk=info,tower_http=info`)

## 代码结构

```
src/
  main.rs            入口
  config.rs          命令行配置
  error.rs           统一 API 错误
  state.rs           运行期状态、数据目录、验证码、引导
  db.rs              SQLite 访问层(WAL)与建表(含运行期开关 settings)
  domain/            纯业务逻辑(不依赖 HTTP)
    paths.rs         路径规范化与校验(含 Windows 保留名)
    auth.rs          密码哈希、令牌、会话提取
    perms.rs         访问级别与目录规则
    fsx.rs           文件系统原语(原子写、目录统计、流式 ZIP 打包)
    uplink.rs        分片上传状态机与流式合并
    media.rs         ffmpeg 转码与缩略图任务、上传视频自动转码替换
    ticket.rs        下载直链 HMAC 签名
  api/               HTTP 处理层(按模块拆分)
  tlsrun.rs          rustls 热加载监听
web/                 前端(原生 ES Modules,按模块拆分,内嵌进二进制;含 logo.svg 与 favicon)
assets/ndisk.ico     Windows 可执行文件图标(多尺寸 16-256)
build.rs             Windows 下把图标写入 exe 资源(其它平台无操作)
tests/               端到端验证脚本(API 冒烟、移动端手势与 UI 审查、内存压测)
```
